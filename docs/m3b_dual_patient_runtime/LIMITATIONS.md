# 范围与M3-C之前的限制

本轮不放宽180秒治疗协议。A在180秒合法执行，B资源恢复于181秒后治疗被阻断，因此即使两个独立Engine、同步时钟、竞争和等待均得到原生证明，整体也只能是M3B_DUAL_PATIENT_PARTIAL，不能写成双患者治疗PASS。

两个Engine使用相同StandardMale固定输入，不代表两个独立验证的人体模型。没有增加新患者类型、伤情严重度、组合或动作；没有更改基线SHA、12动作参数、14条规则或M1模型。

1秒资源等待来自首次后续采样确认策略，不是臆造临床治疗时长。未研究即时/0.02秒确认的最早可释放时刻。保持1秒同步采样；后续299秒是协议阻断后的观察，不能混称资源排队。

中央账本是单进程内存权威，导出的SHA/事件日志不能用于崩溃恢复后重新提交治疗。没有跨机器容错、Worker重启恢复、抢占、自动重规划、多资源/多动作或通用DAG。

全局屏障保证正常事件边界一致，不能保证两个原生进程原子同时推进。一个Worker推进失败时另一方可能已到下一步；此时停止并记录分歧，不能回滚或继续调度。Worker通讯目前是本机可信Pipe，不是网络服务认证协议。

控制器复用CaseRuntime内部registry/_prepared以拆分初始化阶段，属于需要随上游接口变化维护的窄耦合；已有单患者prepare/runner保持不变。

正式评价仍有StandardMale/Soldier、匹配Control、独立证据合同限制。B未治疗，不能通过放宽证据规则给它评分。执行accepted/完成不等于疗效有效。

M3-C可以基于本轮竞争反馈、释放唤醒、版本及身份接口设计资源决策实验，但要研究“排队后两名患者均完成合法治疗”，必须先另行确定并验证相应时序研究协议。本轮不开发M3-C，不让Agent绕过时间约束。
