# 已知限制与验收边界

1. 10/10 是固定研究配置的受限仿真工程验收，不代表临床安全、患者整体安全、治愈或可部署生产。所有 `production_enabled` 仍为 false。
2. 血胸及 CO 的 Hypernatremia、血钠轨迹、其他异常和原始数值完整保留。高钠原因尚未完全确定；两种健康初始化均出现同样轨迹。已接受的是限定研究工程风险，不是认定其临床无害或已解决。血胸只确认停止持续出血与真实胸管引流机制；CO 只确认停止环境暴露及 CO 负荷下降。
3. 风险接受仅适用于已经真实验证的固定 Pulse 4.3.2 Profile。既有 1e−7 确定性轨迹符合度精度不是临床血钠阈值。超出既有证据、持续恶化、新严重事件、关键缺测、资源或执行约束不满足继续拒绝；不得自动扩大豁免。
4. 环境低氧独立通过机制、安全及真实 E2E 核验，不继承血胸/CO 高钠豁免。
5. 血胸 N1/E1 版本分别为 `301.v2.hemothorax.N1.1` / `301.v2.hemothorax.E1.1`。微小负残余属于限定数值解释；原始负值不改写为零，不等于临床疗效判定。治疗后状态恢复会损失相关残余信息，因此限定连续会话。
6. CO 验证使用 Aorta CO/COHb 读数；不能用始终为零的系统 CO 或含 CO 影响的 SpO₂ 代替该机制证据。暴露路径仅允许已验证的自有治疗前分支。
7. 旧底层合同和历史状态标签保留原义；新统一受限外层的工程准入不追溯篡改旧报告。用户最终确认发生在测试之后，旧测试结果中的 `NOT_RECORDED` 是有效历史记录。
8. 853 是三份最终互斥测试集的合计。重复验证及失败/中断尝试不计入通过数，原件仍保留；环境中的 Python 弃用警告不删改。正式 E2E 的 `accepted_endpoint_state.json` 是通过时状态；随后注入故障以测试拒绝的 `final_state.json` 不应被误认作疗效终点。
9. 不扩展到新伤情、其他严重度/侧别/参数、自由治疗剂量、复杂多伤情组合或其他引擎版本；不评价真实 LLM Agent 规划能力。不构成整个 301 项目的最终验收。
10. 本阶段结束。后续变更必须在此基线上另行版本化研究和验证，不得直接修改已验收固定协议或覆盖证据凑数。
